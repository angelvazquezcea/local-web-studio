# Care plans

Clients renew when they *feel* value during the year. Silence for 11 months followed by an
invoice is how care plans die.

## What a care plan typically covers

- Domain renewal and DNS management; hosting oversight; HTTPS check.
- Backups of the site code (the repo/folder) and content.
- N small changes per year (text, photos, hours, prices, seasonal banner).
- Google Business Profile check (hours, holidays, photos, review replies coaching).
- Yearly report with results (see `analytics-and-reporting`).
- Priority response time (e.g. 48 h working days).
Not included (quote): new sections/pages, new languages, redesign, ads, social media.

## Year-1 value calendar (start at delivery)

| When | Touchpoint |
|---|---|
| +2 weeks | "Is everything ok? Here's how people found you so far" (first numbers). |
| +1 month | Google profile check; nudge to ask 3 happy customers for reviews. |
| +3 months | Seasonal update or a small improvement proactively proposed. |
| +6 months | Short results message: visits, calls/WhatsApp clicks, route requests. |
| Holidays/season | Update hours on Google and the site before the client asks. |
| −30 days to renewal | Yearly report + renewal notice with price and what's included. |
| Renewal | Invoice; thank-you; one idea for next year. |

Each message: 2–5 lines, one number or one concrete improvement, no jargon.

## Handling changes

Log every change in `client.md` under "Care log" with date and whether it counts against the
yearly allowance. Fixes of our own bugs never count. Apply the "propose before changing"
rule for anything beyond a small change.

## Renewals and cancellations

- Remind 30 days before. State price, period, included items, and last year's highlights.
- If the client cancels: thank them, hand over all accesses (domain, hosting, Google, code),
  make sure the domain auto-renew is on *their* payment method, document it. Leave the door
  open. A graceful exit produces referrals.
- If they don't pay: never take the site down or hold the domain hostage — the client owns it.
  Pause changes and support.

## Portfolio view

Keep a table of active care plans (client, start, renewal date, fee, last touchpoint) in
`studio.md` or a `care.md`, and surface the upcoming touchpoints when the user asks "what's
pending".
